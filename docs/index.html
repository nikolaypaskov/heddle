h e d d l e  /ˈhɛd(ə)l/  n. — the loom component that lifts and separates the warp threads. The part that controls the warp.

A terminal with no account, no telemetry, and no company server behind it.

Heddle is a fork of the Warp terminal with everything commercial taken out. There is no sign-in, nothing is uploaded, and Warp's web addresses are not in the app at all — not switched off, not present.

$ heddle

↓ Get the latest release macOS · Apple Silicon (M1+) · signed & notarized

Two things to know before you download

The built-in AI agent does not work. It was designed to talk to Warp's server, and this version has no server to talk to. Claude Code, Codex, Gemini CLI and similar run as ordinary programs and are unaffected.

Apple Silicon Macs only. No Intel Mac, no Windows. Linux is built automatically but not published as a ready-to-run download yet.

Install

1. Download the app
Heddle-aarch64-apple-darwin.app.zip — start here. A terminal-only tar.gz is also published.
2. Unzip with Archive Utility
Double-click it. Avoid third-party unzip tools — some strip the Apple signature, after which macOS refuses to open the app.
3. Drag Heddle.app to Applications
Signed with an Apple Developer ID and notarized by Apple — it opens with a double-click, no security warning.
# prefer the command line? verify, then unpack:
$ shasum -a 256 -c Heddle-aarch64-apple-darwin.app.zip.sha256
$ ditto -x -k Heddle-aarch64-apple-darwin.app.zip .
$ open Heddle.app

What you get

No accountNothing to sign up for, nothing to sign in to
No telemetryNothing about how you use it leaves your machine
No cloudYour history, settings and sessions stay on your computer
Free and openAGPL-3.0. Read it, change it, build it yourself

What is not here

This is not a way to get Warp's paid plan for free. Warp's paid features ran on Warp's servers; removing the sign-in screen does not move them to your machine.

Removed: sign-in and accounts, Drive's cloud sync and sharing, usage analytics, crash reporting, remote configuration, billing and upgrade prompts, and every warp.dev address.

How much of it works today

okThe terminalWorks
okThemes, settings, keyboard shortcutsWorks
okClaude Code, Codex and other CLI agentsRun as ordinary programs
--Warp's built-in AI agentNeeds Warp's server
okDrive — workflows, notebooks, env varsWorks, stored on your machine
--Cloud sync and object sharingRemoved on purpose
--Windows, Intel MacNot built

Heddle is a terminal today, not an AI environment. A replacement agent that talks to a local program instead of a company server is designed but not built; until it is finished and safe, it will not be described as working.

Is this really private?

It is checked automatically, not just claimed. Every time the code changes, a program reads the raw bytes of the built app and fails the build if any Warp address, credential or analytics destination appears in it.

$ ./script/heddle/verify-no-warp-endpoints
PASS: no Warp endpoints, credentials, or telemetry destinations found.

Being straight about the limits: this proves those addresses are not in the app. It does not prove the app opens no connections at all — a service you configure yourself is contacted because you asked for it. Fully proving network silence needs system-call tracing that has not been done yet, and that is stated plainly rather than glossed over.

Questions

Is this legal?
Yes. Warp open-sourced the client under AGPL-3.0, which exists precisely to allow open forks. Heddle keeps the license files and upstream copyright notices, and does not use the “Warp” trademark.
Does this unlock paid Warp features?
No. Paid entitlements are enforced on Warp's servers, and there is no server here. The value is privacy and independence, not free Pro.
Can I use it fully offline?
Yes — that is the entire point. No sign-in, no cloud sync, no telemetry, and no server for it to talk to.
Will it get an AI agent?
A local replacement over ACP is designed but deliberately not shipped — a half-finished agent that runs commands without working permission prompts is worse than none.
