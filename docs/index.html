HEDDLE(1)User CommandsAGPL-3.0

heddle

/ˈhɛd(ə)l/  n.

the loom component that lifts and separates the warp threads — the part that decides which threads rise and which stay down.

A terminal with no account, no telemetry, and no company server behind it.

Heddle is a fork of the Warp terminal with everything commercial taken out. There is no sign-in, nothing is uploaded, and Warp's web addresses are not in the app at all — not switched off, not present.

↓ Get the latest release macOS · Apple Silicon (M1+) · signed & notarized

01What the heddle separated

Warp's paid features ran on Warp's servers. Removing the sign-in screen does not move them to your machine — this is not a way to get Warp's paid plan for free. What is left is a terminal that works entirely on its own.

Threads kept — local
  • The terminal: blocks, editor, keyboard shortcuts
  • Themes and settings
  • Drive — workflows, notebooks, environment variables
  • Claude Code, Codex, Gemini CLI as ordinary programs
  • Update notifications, opt-in and asked once
Threads cut — remote
  • Sign-in and accounts
  • Drive's cloud sync and object sharing
  • Usage analytics and crash reporting
  • Remote configuration
  • Billing and upgrade prompts
  • Every warp.dev address

Drive itself stayed. Its workflows, notebooks and environment variables are local information, so removing the cloud sync they used to travel over was never a reason to remove the library. It is on by default and everything in it lives on your machine.

Heddle is a terminal today, not an AI environment. A replacement agent that talks to a local program instead of a company server is designed but not built; until it is finished and safe, it will not be described as working.

03Install

One app, two platforms: a signed .app for macOS and an AppImage for x86_64 Linux, built from the same source by the same release.

Download the app

Heddle-aarch64-apple-darwin.app.zip on macOS. On Linux, heddle-x86_64-unknown-linux-gnu.tar.gz, which contains Heddle-x86_64.AppImage — unpack it, make it executable, run it.

macOS: unzip with Archive Utility

Double-click it. Avoid third-party unzip tools — some strip the Apple signature, after which macOS refuses to open the app.

macOS: drag Heddle.app to Applications

Signed with an Apple Developer ID and notarized by Apple, with the ticket stapled — it opens with a double-click, no security warning to click past.

# prefer the command line? verify, then unpack (macOS):
$ shasum -a 256 -c Heddle-aarch64-apple-darwin.app.zip.sha256
$ ditto -x -k Heddle-aarch64-apple-darwin.app.zip .
$ open Heddle.app
# linux:
$ shasum -a 256 -c heddle-x86_64-unknown-linux-gnu.tar.gz.sha256
$ tar -xzf heddle-x86_64-unknown-linux-gnu.tar.gz
$ ./heddle-x86_64-unknown-linux-gnu/Heddle-x86_64.AppImage

04Finding out about new versions

Heddle asks once, on first run, and does nothing until you answer.

Change your mind any time in Settings → Privacy. If you say yes, it fetches a small file from this repository over HTTPS. It sends no account, no identifier and no usage data — the request deliberately avoids the app's normal HTTP client, which would have attached a client ID.

Before anything is installed, a downloaded build must be notarized by Apple and signed by this project's Developer ID — a validly-signed build from anyone else is refused — and its version is read from the downloaded bundle itself, so a manifest cannot advertise one version and ship another. You are told what is available before the download starts.

If you say no, it never contacts anything.

05Is this really private?

It is checked automatically, not just claimed.

Every time the code changes, a program reads the raw bytes of the built app and fails the build if any Warp address, credential or analytics destination appears in it.

$ ./script/heddle/verify-no-warp-endpoints
PASS: no Warp endpoints, credentials, or telemetry destinations found.

Being straight about the limits: this proves those addresses are not in the app. It does not prove the app opens no connections at all — a service you configure yourself is contacted because you asked for it. Fully proving network silence needs system-call tracing that has not been done yet, and that is stated plainly rather than glossed over.

06Questions

Is this legal?
Yes. Warp open-sourced the client under AGPL-3.0, which exists precisely to allow open forks. Heddle keeps the license files and upstream copyright notices, and does not use the “Warp” trademark.
Does this unlock paid Warp features?
No. Paid entitlements are enforced on Warp's servers, and there is no server here. The value is privacy and independence, not free Pro.
Can I use it fully offline?
Yes — that is the entire point. No sign-in, no cloud sync, no telemetry, and no server for it to talk to. The opt-in update check is the only thing that ever reaches the network on its own, and only after you say yes.
Will it get an AI agent?
A local replacement over ACP is designed but deliberately not shipped — a half-finished agent that runs commands without working permission prompts is worse than none.
Why is the built-in agent gone but Claude Code fine?
The built-in agent was a client for Warp's server; with no server, it has nothing to talk to. Claude Code, Codex and Gemini CLI are separate programs that run in any terminal — Heddle does not mediate them, so they are unaffected.
